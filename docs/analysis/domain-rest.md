# domain-rest

## Summary
The rest of MonHub is mostly Pokemon code: save parsing, Dex, Nuzlocke, the randomizer and PMD sprites. RetroHub cannot use any of its domain logic, but several general-purpose patterns sit inside it.

(1) SaveInspector.cs reads trainer, playtime, badges, Dex and party from Gen1-7 saves by decoding the binary layout. That is useless for RetroHub. Its caching is generic: results are cached per (path, size, mtime), files over a size cap are skipped, and a file written in the last 10 seconds is not cached because the emulator may still be writing it.

(2) Nuzlocke.cs and AppConfig.cs show a solid JSON settings pattern. Loading tolerates nulls in hand-edited files. A broken file is first copied to "<file>.kaputt", and a fresh default is used. Saving goes through SafeFile, which writes a temp file and then moves it over the target in one step.

(3) The pages (Dex, Nuzlocke, Randomizer, Options) share a page skeleton. Each page implements IHubPage.Refresh() as async void. It uses a _loadId counter to drop stale results, and compares a signature string so the UI is only rebuilt when the data actually changed. The header is uppercase label + title + muted summary, with a search box on the right that has an overlay hint and a magnifier Path. Filters are chip RadioButtons. There is an empty-state panel and a debounced autosave (DispatcherTimer 600 ms, plus a save on Unloaded).

(4) DexPage solves a real Avalonia gap that matters for a cover grid: a virtualizing wrap grid. It cuts items into rows that fit the width and puts the rows in a virtualizing ListBox, rebuilding only when the column count changes.

(5) RandomizerPage plus RandomizerProcess/RandoSettingsFile are a complete "run an external tool in the background with live log and busy state" flow. It covers a free-disk-space check, ProcessStartInfo.ArgumentList, redirected stdout/stderr marshalled to the UI thread, an exit code via TaskCompletionSource, cleanup of partial output and a wobbling busy icon. The page also has a responsive two-column to stacked layout and filter ComboBoxes filled from the values that actually occur.

(6) SettingsEditorWindow builds a settings form at runtime from (name, type, value, choices) tuples: bool becomes a CheckBox, enum a ComboBox, int a validated TextBox. It shows a hand-picked group first and an "expert" Expander for the rest, and counts changes. This fits per-emulator or per-core options in RetroHub.

(7) OptionsPage has a theme gallery that draws a tiny app preview in each theme's colours. It also has a motion setting (follow Windows animation effects / all / calm / off), a language switch that restarts the app (with a confirmation if a game is running), and a "portable root folder" panel.

(8) Shared/Sprites.cs holds a generic strip-sprite animator (SpriteAnimator), but it is tied to static avares sprite registries. It pauses when the sprite is invisible, the window is inactive or minimized, a dialog is open, or motion is off, and it runs at background dispatcher priority. It also has a Game Boy four-green tint filter.

(9) tools/*.py are offline asset generators (PMD sprites, PokeAPI names and routes, fonts, credits). Only build_icons.py, a procedural 32px pixel-icon generator for MonHub's own GPL icons, and the font/.ico steps in build_assets.py are worth keeping.

(10) Assets: Species (809 PNG, 3.1 MB), Sprites (31), Portraits (6 Porygon faces) and Nuzlocke/routes.json are Pokemon/PMD content under CC BY-NC and must not go into RetroHub. Icons (14 own GPL icons) and Fonts (Silkscreen, Pixelify Sans, Press Start 2P, all OFL) can be reused.

D:\Retro: theme\es-theme-nova is a Batocera EmulationStation theme ("Nova v2", formatVersion 7). It has theme.xml (design tokens: colours, Poppins type scale, radii, motion) and views (gamelist "grid", system, menu, screen), plus art and fonts. _system_v1/_v2.xml and _gamelist_v1/_v2.xml are earlier drafts of views/system.xml and views/gamelist.xml. They are theme views, not system definitions. theme\tools are Batocera-side helper scripts: SSH deploy/screenshot/key-sending, a pre-rendered blurred-background cache (nova-ambient.py), a ROM-folder watcher that reads es_systems.cfg extensions and starts the scraper (nova-watcher.py), a now-playing card, and art generators. theme\web is a PIN-protected phone remote control (Python stdlib web server + index.html) for WiFi, Bluetooth and system on the console.

D:\Retro has no platform catalog. There is no es_systems.cfg or yml, no extension lists and no emulator command lines anywhere. The only platform hints are Batocera system short names used in carbon-theme art paths (${system.theme}) and the es_systems.cfg parser in nova-watcher.py. The real catalog sits inside the Batocera image in D:\Retro\download (4.3 GB .img.gz, at /usr/share/emulationstation/es_systems.cfg), and is easier to take from the batocera.linux / ES-DE sources. D:\Retro\BIOS holds a per-system folder layout with only 2 files: PS1/eigenesbios.bin (512 KB, user-named) and PS2/ps2-bios-all-bios.zip (14 entries: several PS2 BIOS sets with their .NVM/.MEC/.EROM/.ROM1/.ROM2 companion files). That shows RetroHub must identify BIOS files by hash/size, not by name, and must handle zips.

## Pitfalls
- SaveInspector.cs, Nuzlocke.cs, Species.cs/SpeciesData.g.cs, DexPage, NuzlockePage, RandomizerPage, all of Rando/* (randomizer, RareCandyPatch, SpoilerSummary, cheats), tools/build_species|build_sprites|build_nuzlocke|build_credits|build_presets, tools/cheatlab: Pokemon-only domain logic. Do not port. Playtime in RetroHub must come from process run time, not from parsing saves.
- Assets/Species (809), Assets/Sprites (31), Assets/Portraits (Porygon) and the monhub.ico Porygon face are PMD Sprite Collab art under CC BY-NC 4.0 plus Pokemon IP. Do NOT ship them in RetroHub. Same for Assets/Nuzlocke/routes.json (PokeAPI data, no use). The OptionsPage credits text (L46-54 in .cs) is Pokemon-specific.
- Code is a WPF port running on a compat shim (Compat.cs L1-22: global using FrameworkElement=Control, DependencyObject=AvaloniaObject, BitmapSource=IImage, Brush=IBrush, enum Visibility, MessageBox, DialogResult/ShowDialog wrappers). Copying pages means taking this shim along. For a fresh RetroHub use native Avalonia (IsVisible, async dialogs) instead.
- Sprites.cs is coupled to the RandoApp namespace, the static All registry (SpriteData.g.cs generated by build_sprites.py), the avares://MonHub/Assets/ root, Sprites.MoreSprites set by Species.Register(), HubWindow.Blocked/BlockedChanged, Compat.WindowOf and Compat.SystemAnimations. The Frames cache is an unbounded Dictionary and not thread-safe (UI thread only). Fine for ~1000 tiny strips, wrong for thousands of cover images: use Bitmap.DecodeToWidth + an LRU cache for box art.
- Sprites.Cut assumes 4 bytes/pixel and equal-width frames in a horizontal strip; each frame becomes its own WriteableBitmap. OK for pixel sprites, wasteful for large images.
- RandomizerProcess.Run has no cancellation, kill or timeout. It calls proc.WaitForExit() and Dispose inside the Exited handler and post-processes files (TakeAppendedName) on a thread-pool thread. Add CancellationToken + Kill(entireProcessTree) for RetroHub tools.
- RandomizerPage.Refresh/RandomizeAsync etc. are async void event-style methods; exceptions are swallowed to Debug.WriteLine. Acceptable for UI handlers, but keep the try/catch discipline if copied.
- NameDialog.Problem() messages are hard-coded German (not Txt.L), a localisation bug. Don't copy it as is.
- OptionsPage language change needs a full App.Restart because pages and static tables (e.g. SpeciesChoice.All, SettingsEditorWindow.Curated/ChoiceLabels static readonly with Txt.L) are built once. Avoid static localized readonly fields in RetroHub if a live language switch is wanted.
- SettingsEditorWindow.FindInvalid marks bad fields through Tag="invalid" and walks LogicalChildren. That is fragile; prefer a validation flag in a view model.
- DexPage row chunking hard-codes an 18px scrollbar allowance and the cell step (Width+8). Controller navigation across chunked rows is not implemented (mouse UI). RetroHub must add focus handling.
- SaveInspector.Read caches per (path,len,mtime,family) but never invalidates by family/layout changes, and Cache.Clear at >2000 entries is crude. Fine as an idea only.
- RareCandyPatch.Apply writes the ROM in place with File.WriteAllBytes, not atomically. Don't copy that style for anything that modifies user files.
- D:\Retro contains NO system definitions: no es_systems.cfg/yml, no extension lists, no emulator command lines. _system_v*.xml and _gamelist_v*.xml are only drafts of the theme's view XML (system dropdown / game grid). Don't treat them as a platform catalog. Get Batocera's es_systems (batocera.linux repo, es_systems.yml) or ES-DE's es_systems.xml as the external reference, or read /usr/share/emulationstation/es_systems.cfg from the Batocera 43.1 image in D:\Retro\download (squashfs inside a 4.3 GB img.gz; not extracted).
- The Nova theme depends on Batocera-only features (formatVersion 7, itemTemplate/storyboard, screenshader blur.glsl, ${carbon} = es-theme-carbon art at /usr/share/emulationstation/themes/es-theme-carbon/art for logos/consoles/backgrounds). The XML cannot be loaded by RetroHub; use it as a visual spec only. Poppins (OFL) is in es-theme-nova/fonts and theme/_dl.
- theme/tools scripts hard-code the console IP 192.168.178.103, root SSH, the ES HTTP API at 127.0.0.1:1234 and scratchpad paths from an older session (perf.sh, shot.sh). Not portable. Note that nova-watcher.py drives Batocera's scraper by simulating key presses with xdotool, a hack that should not be copied.
- D:\Retro\backup\stick-backup.tgz contains .ssh/authorized_keys, ssh/dropbear_ed25519_host_key and batocera.conf (may contain WiFi credentials). Sensitive: only listed, not read; never bundle or parse it.
- BIOS file names are user-chosen (PS1\eigenesbios.bin) and PS2 BIOS sets come zipped with companion files. Don't detect BIOS presence by fixed file name. Hash-verify and map to the names each emulator expects (DuckStation/PCSX2 scan folders; RetroArch cores need exact names like scph5501.bin).
