# config-setup

## Summary
MonHub's config, setup and packaging layer is small and mostly generic. HubPaths.cs (75 lines) is a static class that computes every path from AppContext.BaseDirectory. The exe lives in <Root>\System\App, and Root is two levels up, but only when the parent folder is literally named "System". Otherwise, for example during development, Root falls back to the exe folder itself. Player folders (ROMs, Randomisierte ROMs, Spielstände, Fangames) sit at Root. Program folders sit under System\ (App, Emulatoren\<emu>, Einstellungen, BIOS). Emulator exes are not stored in config; Os.FindProgram(folder, name) finds them each time by name pattern (exact name.exe first, then name_*.exe / name.*.exe, preferring x64, never side tools like azahar-room.exe). Settings are System.Text.Json files in System\Einstellungen. MonHub.json holds HubConfig, a POCO with a static Current singleton and Load()/Save(); Randomizer.json holds Rando/AppConfig. Both write atomically through Shared/SafeFile.cs (write to a temp file, then File.Move with overwrite). A file that fails to parse is copied to "<file>.kaputt" and the app starts with defaults. Legacy.cs renames settings files left by older versions on startup, and an old enum id is mapped in Load. There is no schema-version field: migrations are done by renaming properties and by FillMissing(). "Setup" is HubSetup.EnsureAll(). It runs on every start (App.Prepare) and again in the background when the app gets focus back (EnsurePending). It creates the folders and patches each bundled emulator's own config file (melonDS TOML, DeSmuME/mGBA INI, Azahar qt-config.ini) so saves, savestates and the ROM dialog point at the portable folders. It turns on portable mode (an empty mGBA portable.ini, an Azahar "user" folder) and skips any emulator that is running, because emulators rewrite their config on exit. Nothing is unpacked from Hub-Deps at runtime: Hub-Deps is only a download cache for the build, with SHA-256-pinned official releases. build.ps1 unpacks them into Hub-Build\System\Emulatoren, and Inno Setup (MonHub.iss) ships that tree. On Linux, install.sh unpacks the AppImages once. Publishing uses `dotnet publish -c Release -r win-x64 --self-contained true` into System\App. It is not single-file, not trimmed and not ReadyToRun, with DebugType none, and gives 228 loose files, about 150 MB including a jlink'd JRE. The csproj itself says SelfContained=false; the self-contained switch comes only from the command line. Logging is minimal. Program.cs uses Avalonia's .LogToTrace(), and the many swallowed exceptions go to Debug.WriteLine (which does nothing in Release). The only file log is System\Einstellungen\MonHub-crash.log, written by App.OnUiError (overwritten on each first UI error, then a message box, with loop protection) and LogBackground (appended, timestamped, for AppDomain.UnhandledException and TaskScheduler.UnobservedTaskException). Only one instance runs per install folder, through a named Mutex built from a SHA1 of the Root path. A second start touches a ".show" file that the running instance watches with a FileSystemWatcher, which brings its window to the front. Tests (MonHub.Tests) use xUnit 2.9.3 with Microsoft.NET.Test.Sdk and coverlet, and reference the app project through InternalsVisibleTo. They cover only pure logic (SafeFile, the Txt language, ScreenLayout math, ControlSettings to emulator-config translation, the save parser with fixture .sav files), use temp directories, and have no UI or headless Avalonia tests.

## Pitfalls
- Root detection depends on the parent folder being named exactly 'System' (HubPaths.cs line 21). Otherwise Root becomes the exe folder, so 'dotnet run' quietly creates ROMs, Saves and so on inside bin\Debug\net10.0. RetroHub needs an explicit override or marker.
- All paths are static properties computed from AppContext.BaseDirectory (HubPaths), so tests cannot redirect them. MonHub.Tests therefore never tests HubConfig.Load/Save, HubSetup or Legacy against a real folder. Make the paths injectable.
- Folder names are German and contain an umlaut ('Spielstände', 'Emulatoren', 'Einstellungen', 'Randomisierte ROMs') and stay German in both UI languages. RetroHub should use English ASCII names.
- The csproj says <SelfContained>false</SelfContained> while build.ps1 passes --self-contained true. The csproj also has no PublishSingleFile, PublishTrimmed, ReadyToRun or InvariantGlobalization, so the output is 228 loose files in System\App. Put the publish profile (pubxml) in the project, not only in the script. Trimming would break today because System.Text.Json uses reflection (no JsonSerializerContext) and Avalonia uses reflection bindings (AvaloniaUseCompiledBindingsByDefault=false).
- DebugType none means no PDBs, so MonHub-crash.log stack traces have no line numbers.
- The crash log is overwritten by File.WriteAllText on the first UI error (App.axaml.cs line 36) and has no timestamp, while background errors are appended with timestamps. It is never rotated, and Program.cs LogToTrace plus Debug.WriteLine produce nothing in Release. There is effectively no diagnostic log. Don't copy that.
- Bare 'catch { }' blocks are everywhere: HubConfig.Load line 93, AppConfig.Load line 56, Txt.FromSettings. Errors vanish silently; log them.
- HubConfig.Current is a mutable static singleton. Save() runs synchronously on the UI thread (for example ToggleFavorite, line 116, saves the whole file on every click), and HubSetup also writes HubConfig from a background thread (Azahar.cs lines 223-224) with no locking.
- Favorites are keyed by ROM file name only (HubConfig.cs lines 73-74, 110-117). Two platforms with the same file name collide, and renaming a file loses the favorite. Use a stable game id or a relative path plus platform in RetroHub.
- There is no config schema version. Migrations come from renaming JSON properties (AzaharSixtyFps leaves the old 'Azahar60Fps' default behind, which a test checks) and from Legacy.MoveSettings. Workable but fragile.
- Txt.FromSettings parses MonHub.json a second time before HubConfig.Load, which duplicates reads.
- HubSetup.EnsureAll rewrites every emulator config on every start and on focus changes, which costs disk I/O. IsRunning matches processes by name prefix (for example 'mGBA'), so any process whose name starts that way, even an unrelated one, blocks provisioning. Match by exe path under the Emulators folder.
- Doc comment bug in HubSetup.cs lines 353-354: two consecutive <summary> tags, and SetIni's comment sits on RemoveIni.
- SetIni matches keys case-insensitively, while SetToml matches 'key ' / 'key=' with Ordinal comparison. INI sections are compared case-insensitively, TOML sections exactly. Keep that if copying.
- First-run setup does NOT unpack emulators from Hub-Deps. Hub-Deps is only the build machine's cache. If RetroHub wants on-demand emulator downloads or installs, that is new work; MonHub has no runtime downloader or unpacker on Windows.
- build.ps1 deletes Hub-Build entirely (Remove-Item -Recurse -Force) and deletes the source project's bin/obj after publishing. It also hard-codes the 7-Zip and Inno Setup paths ($env:ProgramFiles\7-Zip, $env:LOCALAPPDATA\Programs\Inno Setup 6). It also builds the Java RandoHelper, jlinks a JRE and runs the Python asset generators. The Java and Python parts are Pokémon-specific and can be dropped.
- app.manifest declares only supportedOS (Windows 10). It has no longPathAware, although MonHub already fights path length (Azahar SD paths, Azahar.cs around line 67-75). RetroHub should add <longPathAware>true</longPathAware> (and dpiAware if needed; Avalonia handles DPI itself).
- The uninstall WMI check (MonHub.iss lines 171-198) only runs on uninstall; Setup relies on Inno's default Restart Manager closing apps. App.ShuttingDown suppresses dialogs then. Keep that flag if you copy the installer behaviour.
- Tests have no UI coverage (no Avalonia.Headless), and FindProgram_TakesTheEmulator_NotASideTool passes silently on non-Windows ('return' instead of a skip). The Pokémon-specific tests (SaveInspector, ControlsTests for melonDS/Azahar/mGBA key codes) are only useful if RetroHub keeps those emulators.
- MonHub source uses WPF-name aliases (global using FrameworkElement = Avalonia.Controls.Control; Compat.cs lines 10-15) and a homemade Visibility enum carried over from its WPF past. Don't carry that into a fresh Avalonia codebase.

## Key details
PORTABLE LAYOUT (HubPaths.cs):
  AppDir => AppContext.BaseDirectory.TrimEnd(sep)
  Root => app.Parent?.Name.Equals("System", OrdinalIgnoreCase) == true && app.Parent.Parent != null ? app.Parent.Parent.FullName : app.FullName
  <Root>\ROMs, \Randomisierte ROMs, \Spielstände\{melonDS,DeSmuME,mGBA,Azahar,GBA und GB}\[Savestates], \Fangames
  <Root>\System\App (exe, install.ini, Settings\*.rnqs, jre\, Lizenzen\), \System\Emulatoren\<emu>, \System\Einstellungen (MonHub.json, Randomizer.json, MonHub-crash.log, .show, Nuzlocke\), \System\BIOS
  RomExtensions = [".nds",".gba",".gbc",".gb",".3ds",".cci",".cxi",".cia"]

CONFIG: System.Text.Json, JsonSerializerOptions { WriteIndented = true }, reflection-based. HubConfig properties: Fangames(List<{Name,Path}>), Theme, Motion(MotionLevel? All/Calm/Off), Language("en"/"de"/null), TrainerName, Controls(ControlSettings?), AzaharLook(int, applied-once flags), TourSeen, InstallSeen, TourLater, AzaharSixtyFps, GamesInOwnWindow, DsScreens/ThreeDsScreens(ScreenArrangement), Favorites(List<string> of file names).
  Load: if exists -> Deserialize ?? new(); catch -> File.Copy(path, path + ".kaputt", true); return Current = new().
  Save: Directory.CreateDirectory(SettingsDir); SafeFile.WriteAllText(path, Serialize(this)).
SafeFile.Write: tmp = $"{path}.{Guid.NewGuid():N}.monhub-tmp"; write(tmp); File.Move(tmp, path, overwrite: true); finally delete tmp if left. UTF-8 without BOM.

SETUP: App.Prepare(): Legacy.MoveSettings -> Txt.ApplyCulture -> ... -> HubConfig.Load -> HubSetup.EnsureAll (lock Gate; CreateDirectory x10; TryRun(EnsureMelonDS/DeSmuME/MGBA/Azahar/RandomizerConfig)) -> HubThemes.Apply -> HubMotion.Apply.
  melonDS: SetToml(null,"LastROMFolder"), ("Instance0","SaveFilePath"/"EnableCheats"/"SavestatePath"), BIOS keys in [DS]/[Emu]; Quote() = "\"" + path.Replace('\\','/') + "\"".
  DeSmuME desmume.ini [PathSettings] Roms/Battery/States. mGBA: create empty portable.ini; config.ini [ports.qt] savegamePath/savestatePath/lastDirectory. Azahar: create user\ folder (portable), user\config\qt-config.ini: check_for_update_on_start=false, romsPath, sdmc_directory.
  Running emulator -> _pending = true; EnsurePending() re-runs on Task.Run with Interlocked guard.

PUBLISH: dotnet publish MonHub.csproj -c Release -r win-x64 --self-contained true -o Hub-Build\System\App (no single-file, no trim). csproj: net10.0, WinExe, Nullable, ImplicitUsings, Version 2.10.0, DebugType none, ApplicationIcon monhub.ico, ApplicationManifest app.manifest, NoWarn CA1416, packages Avalonia/Avalonia.Desktop/Avalonia.Themes.Simple/Avalonia.Fonts.Inter 11.3.22 + System.Drawing.Common 10.0.0.
  Pinned deps: melonDS-1.1-windows-x86_64.zip, desmume-0.9.13-win64.zip, mGBA-0.10.5-win64.7z (7z.exe), azahar-windows-msvc-2126.1.2.zip; Get-Dep(url) caches into ..\Hub-Deps and Assert-Hash.
  Inno: AppId {9B6C2F4E-3E1A-4B8D-A7C2-5D0E8F1A2B77} (do not reuse), PrivilegesRequired=lowest, DefaultDirName={%USERPROFILE}\MonHub, [Dirs] Flags: uninsneveruninstall, [Files] Excludes "melonDS.toml,*.rnqs" + onlyifdoesntexist copies, [INI] install.ini Setup/Version, Stamp={code:InstallStamp} (GetDateTimeString('yyyymmddhhnnss')), Language={language}; [UninstallDelete] {app}\System; RunningFromApp() via CreateOleObject('WbemScripting.SWbemLocator') 'SELECT Name, ExecutablePath FROM Win32_Process'.

CRASH/LOGGING: Program: AppBuilder.Configure<App>().UsePlatformDetect().WithInterFont().LogToTrace(); [STAThread] Main => StartWithClassicDesktopLifetime(args).
  Dispatcher.UIThread.UnhandledException += OnUiError (log -> e.Handled = true -> if _reporting/ShuttingDown return -> if < 3 s since last -> Shutdown(1) -> MessageBox.Show(msg + "Details: {log}") -> if MainWindow not visible Shutdown(1)).
  AppDomain.CurrentDomain.UnhandledException and TaskScheduler.UnobservedTaskException (a.SetObserved()) -> LogBackground append "[yyyy-MM-dd HH:mm:ss] Hintergrund:".
